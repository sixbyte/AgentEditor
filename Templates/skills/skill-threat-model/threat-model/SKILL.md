# Threat Model

1. Define scope, protected assets, actors, assumptions, and out-of-scope systems.
2. Map data flows, entry points, privilege transitions, trust boundaries, and third parties.
3. Describe realistic abuse cases and preconditions.
4. Rank risk using impact, likelihood, and existing controls.
5. Recommend preventive, detective, and recovery controls with owners and verification steps.

Keep unknowns explicit. Do not invent architecture details; request or inspect the evidence needed to resolve them.
