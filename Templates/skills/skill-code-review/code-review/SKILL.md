# Code Review

## Focus
- Correctness and edge cases
- Security / data loss risks
- API and behavior regressions
- Test coverage gaps
- Clarity of naming and structure (only when it blocks understanding)

## Output
1. Summary (1–3 sentences)
2. Findings ordered by severity (blocker / major / minor)
3. Open questions
4. Suggested next steps

Do not nitpick style that a formatter or linter already handles.
